pllsim v0.9.3 — the contract verified across the parameter space, the divider that follows the frequency plan, and a health check

Thirteen merged changes had accumulated on `main` above v0.9.2 without a
version or a notes file — the same precondition that once produced an
untagged v0.9.1.  This release names them.  Modelling numbers change only
where a defect is stated below; no preset's stock jitter figure moves.

## The linear model and the time domain are now checked everywhere, not at fifteen points

The two domains are required to agree within 2–3 dB, and until now that was
verified at one preset per architecture, one seed.  Changing the frequency
plan or the bandwidth opened gaps nothing measured.

`pllsim.validation.compare_domains` is the one comparator: five hand-copied
test blocks retired onto it with their tolerances byte-identical, the band
clipped to where both estimates mean something with every clip recorded,
thin bins reported instead of dropped, and a jitter pair integrated over the
*same* band (the headline pair never was, whenever `int_band` reached past
0.45·fref — the simulation now says so in a note).

`validation.BOUNDARIES` registers each capability limit as a predicate with a
measured allowance; the engines' runtime notes and the sweep's tolerance
contract call the same functions, so a warning and its test cannot drift
apart.  A 48-point sweep (UGB, frequency plan, near-integer fractions, a few
secondary knobs) runs in its own CI job under one contract: over tolerance
with no boundary flag active is a defect and fails; a declared flag that does
not fire fails too.  Twelve measured gaps are pinned and re-measured on every
push, in both directions.

What it measured: continuous-time peaking in the CPPLL/SPLL model grows from
2.1 dB at the stock UGB = fref/20 to 7.25 dB at fref/9.6, the deepest loop
the synthesizer will build; the fractional SSPLL's stock point sits a flat
−6.8 dB below the model because the DSM/DTC residual is budgeted as white
and the truth is tonal; the BBPD linearization reads +3.3 dB in-band, inside
the +2..4 dB the documentation had always claimed and never measured; the
integer-N SSPLL (exact z-domain) is robust everywhere swept.

Two defects came out of it.  `loop_metrics` counted unity-gain crossings
above fref/2, where a sampled response is periodic — the stock SSPLL reported
15 crossings on a healthy loop.  And the sweep caught its own harness twice:
scaling fref on a fractional preset without keeping the fraction consistent
fabricated 12–16 dB "gaps" that were an unlocked loop wandering.  Three wrong
pins were removed with the reason recorded in place.

## A phone found that pitfall in the product, and the divider now follows the plan

Editing fref from 52 to 104 MHz on the fractional-SPLL workbench left fout
and the fraction untouched; the divider locked 13 MHz from fout, the FLL and
the PD fought forever, and the page showed 1.6 ns of "jitter".

`frac.frac` only ever had one correct value, `(fout/fref) % 1`, so it is no
longer an input: every GUI edit derives it, the field is gone from all three
forms and from the generated config reference, and the same edit now locks
at fout in 2.0 µs at 143 fs.  The construction-time refusal stays as a
backstop for hand-built configs — CPPLL and ADPLL, which never had one,
check the relation now too.

## A loop that never reaches the configured fout says so

An audit of fref/fout-only edits on all fifteen presets found ILCM and MDLL
silently railing: fout×2 is a legal integer multiple the oscillator cannot
reach, and the run read as an ordinary result 12 / 2.4 GHz off target with
no lock detector to hint.  `postprocess` now measures the tail frequency
error against fout with the same fref/1000 criterion `compare_domains` uses
to refuse an unlocked loop, and notes it.  `MDLL.simulate` also never
validated the integer multiple (`analyze` and ILCM did) and ran on a rounded
N; it refuses like the others.

## Two calculators, on all three surfaces

A phase-noise unit converter (degrees / RMS jitter / integrated dBc at a
carrier, both dBc conventions shown, 3.0103 dB apart) and a figure-of-merit
calculator (PLL jitter FoM and VCO FoM; power is an input, because nothing
here models it).  The FoM is anchored on a published triple — Dartizio'23's
77 fs, 17.2 mW and −249.9 dB — reproduced, not typed.

## Android: two APKs per build, a drawer, zoomable plots with a readout cursor

Each Android run now ships an interpreted APK and one with the modelling
packages Cython-compiled to `.so`; the workflow looks inside both rather than
trusting the build log.  The navigation comparison settled on the left
drawer.  Plots zoom on every surface and a cursor lists every curve's value
at the pointer; the IPN breakdown pie appears for every preset.

## A health check, and what it changed first

An audit of the whole repository (26 findings) put the risk in verification
blind spots rather than code quality.  The first ones closed are the ones
that contradicted our own rules: `docs/index.html` claimed 452 tests against
770 because the count test only read the README; the deck's binary check
skipped on every CI run because python-pptx was never installed; and the
boundary register promised a runtime note for every limit while the flicker
synthesis floor had none — it does now, on the long records that can reach
it.  The rest is a plan.
