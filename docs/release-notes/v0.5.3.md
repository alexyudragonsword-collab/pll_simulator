pllsim v0.5.3 — oscillator control-voltage range, JSSC benchmark presets

Highlights since v0.5.2:

- OscConfig gains a control-voltage range (v_min / v_max, both
  defaulting to None), and freq_law clamps to it.  Without a range
  nothing limited the control voltage, so one band reached any
  frequency and a configured coarse band bank was decorative:
  n_bands and band_step_hz changed nothing measurable.  A band that
  cannot reach the target now rails instead of pretending to.
- Band-bank sizing helpers that a voltage range makes meaningful:
  band_center_hz, band_range_hz, band_covers, band_overlap_hz
  (negative = gap between adjacent bands), band_bank_is_continuous,
  bank_range_hz.  v_for is deliberately left unclamped, so a caller
  can see that a target needs a voltage the varactor does not have.
- Both GUIs expose the range, plus a "coarse band bank" readout
  above the workbench form (bank range, band span, adjacent-band
  overlap, whether fout is reachable at all) — a bank with a gap
  otherwise reads as a loop that will not lock.
- The auto-generated forms no longer drop optional fields: a field
  holding None takes its kind from the annotation, and a blank box
  means None.  osc.v_min/v_max, cp.noise_a2hz and
  sampler.gm_noise_a2hz are editable for the first time.
- The four JSSC literature-anchor configurations are first-class
  presets (ALL_PRESETS now 14): bench_gao09_sspll_55p25m_2p21g,
  bench_dartizio23_adpllbb_500m_9p2515g,
  bench_markulic16_sspll_40m_10p24g,
  bench_markulic16_sspll_frac_40m_10p25g,
  bench_wu19_spll_frac_52m_6p253g — each with paper citations and
  published-vs-model numbers, regression-checked against its
  published jitter class, and selectable from both GUIs.  ex14, ex17
  and the benchmark tests build from them instead of carrying
  duplicate config blocks.

Defaults are unchanged throughout: every existing configuration gets
v_min = v_max = None, which is what the loop already assumed.
