pllsim v0.8.1 — the untested modules, and what testing them found

267 -> 379 tests.  No behaviour changes beyond one GUI caption; this is
the audit's third finding class, "engineering hygiene", worked through.

## What had no tests at all

`plotting`, `montecarlo.plot_mc`, `core.spectrum`, `core.noise`,
`core.engine`, every block in `blocks/`, and `calibration/ftl` were
covered only indirectly, through architecture tests that close a loop
around them.  A closed loop absorbs sign errors and factors of two into
a slightly different jitter number, so those tests would pass with the
block wrong and tell you nothing about which block.

Now pinned individually, against answers computed by hand:

- **spectrum**: `find_spurs` on a synthesized tone of known amplitude
  reads 20log10(A/2) to 0.2 dB; the noise-pedestal subtraction is
  checked by adding noise under the same tone and requiring the same
  answer.  Every architecture's spur number rests on this, and if it
  mis-scaled, every cross-domain check would still pass.
- **jitter**: RMS jitter against a hand-integrated flat PSD, and
  `ipn_dbc` pinned at 3.01 dB below the double-sideband integral,
  because it is quoted from L(f) = S_phi/2 while the rest of the library
  carries S_phi.  Mixing them is a silent 3 dB.
- **noise sources**: the alias factor on sampled sources, 4kTR, the
  quantization slope per order, log-log table interpolation.
- **blocks**: `v_for` inverting the nonlinear frequency law, `kvco_at`
  against a numerical derivative, band-bank overlap sizing, the CP
  segment areas summing to the lumped charge, `drive_fine` resolving a
  1 ps pulse inside a 52 ns step, both DTC declaration styles.
- **calibration**: FLL engage/release hysteresis and drive sign, FTL
  gear shift, LMS convergence to a known gain error, and that a sign-sign
  update moves by mu whether the error is 1 or 1e6.
- **plotting**: every figure function on real results, asserting on what
  lands on the axes rather than on "it did not raise".

## Every Streamlit page's compute path

The existing GUI tests covered "the page imports and lays out".  That
passes for a page whose button raises the instant it is pressed, which
is exactly what the ILCM/MDLL time-domain bug was: both GUIs rendered
perfectly and only the button was broken.  All 13 buttons are now
pressed, including the injection-locked pair that caused it.

These set every numeric control to its minimum first.  The pages default
to production run lengths -- 40 chips of 150k cycles on the Monte Carlo
page -- and the question here is "does the button work", not "is the
answer accurate".  Left at the defaults the file cost three minutes per
CI job, twice per push, out of a metered budget.

## AMS/RNM export: cross-reference checking

No free simulator elaborates Verilog-AMS, so this export had never been
compiled by anything.  The existing checks confirm files exist and
begin/end nest -- which a top instantiating a module that was renamed
would still pass.

Added the part of elaboration that is a text problem: every instantiated
module exists, every named port is a port the module declares, no
instance leaves an *input* floating, no duplicate or self-instantiating
modules, no `nan`/`inf` literals.  This is not "it elaborates" and is
not claimed to be; it is the class of error a rename actually produces.

Writing it produced four findings about the checks themselves, which is
the reason to write the guards:

- The instantiation regex found **zero** instances in the AMS tops, so
  every check was passing vacuously.  Parameter overrides wrap across
  lines and the pattern only allowed spaces.  There is now an
  anti-vacuity test that counts what was parsed and scales its threshold
  with the number of exports.
- `input up, dn;` declares two ports; taking only the first reported
  every second port of a comma list as undeclared.
- ANSI headers have one terminating `;`, so scanning to it filed every
  port under the first direction and called the debug **outputs**
  inputs.  Scanning keyword-to-keyword handles both styles.
- The missing-module check filtered instantiations to modules already in
  the table, which made it incapable of failing.  It now runs unfiltered,
  with a mutation test proving both it and the port check have teeth.

The exports' two shapes are now pinned deliberately: the RNM top is a
flat transplant of the golden engine, so its output stays bit-comparable
against `golden_rnm.csv`, while the electrical AMS top is hierarchical.
A flat electrical top would mean the electrical claim is empty.

## One behaviour change

The Streamlit worst-channel sweep now names the preset it swept, in the
chart title and the caption.  The sweep used to scan a fixed preset
regardless of the selection; that was fixed earlier, but a chart that
does not say what it swept cannot show that it was ever wrong.
