pllsim v0.9.0 — the two GUIs stop drifting

The desktop and web GUIs are meant to expose the same library.  Nothing
compared them, so nothing failed while they diverged, and every gap ran
one way: the Qt side was the one missing things.

## The Qt GUI is bilingual

Streamlit gets this almost free -- it re-runs the whole script on every
interaction, so `L(zh, en)` reading a session variable is enough.  Qt
builds its widgets once and keeps them, so a language switch has to find
every label already on screen and set its text again.

New `guiqt/i18n.py` does the remembering.  `tr(widget, zh, en)` sets the
text for the current language and registers the pair, so `set_lang()` can
re-apply it later; widgets are held weakly, so a torn-down page neither
stays alive nor gets text pushed into a deleted C++ object.  The sidebar
page names come through `on_language_change`, because a list item is not
a widget the registry can reach.

Every page is tested to change visible text on a switch and to change
back, so a page added later without wrapping its labels fails rather
than quietly staying English.

## Monte Carlo: the calibration yield

The web GUI has always reported it and the desktop one never did.  It
answers a different question from the jitter yield: a chip can pass the
jitter limit on a channel that barely exercises the DTC and still ship
with its calibration wrong.  The residual is
`|value * (1 + true_error) - 1|`, since the calibrator converges on
`1/(1+true_error)`.  Reported as "-" when the run carried no calibration
trace, rather than as a number.

## Export: a zip, not only a folder

Also web-only until now, and a directory is awkward to move off a build
machine.  The three-layer bundle zips to whatever path the save dialog
returns; the test opens the result, runs `testzip()`, and checks all
three layers are inside.

That test picks a *fractional* preset deliberately: an integer-N CPPLL
emits no RTL at all, having no MASH, DLF or LMS to generate, so an
integer preset would have tested the zip against the wrong expectation.

## Benchmarks: the re-run button

Present on the web page, absent on the desktop one.  Both now build the
live comparison from the `bench_*` presets rather than from `tests/` --
a packaged build ships no test suite, so importing one there is a
guaranteed ImportError for anyone running the exe.

## Selector -> workbench, finally implemented

Both GUIs described this flow and neither did it.  The Streamlit page
carried a caption telling the user to go to the workbench, pick the
closest preset, and retype fref/fout by hand.

Now each feasible candidate gets a button that opens it directly.  What
crosses over is the candidate object the selector already built -- sized
for the stated requirement -- not the nearest stock preset, so the
workbench shows the design that was actually recommended.  The workbench
grew `load_config()` alongside its preset dropdown, shows a banner while
it is editing a handed-over config, and offers a way back to the presets.

## Tests

379 -> 405, including a check that both GUIs expose the same page set --
the comparison that, had it existed, would have failed on every one of
the gaps above.

Note on running them: the Qt tests skip without PySide6 and its system GL
libraries.  CI installs both, so they run there; a bare checkout skips
them, which is why this drift went unnoticed for as long as it did.
