pllsim v0.6.0 — completeness audit: corrections, symmetry, packaging

This release is the result of auditing the project against what it
claims to do.  Three classes of finding, all fixed here.  Some reported
numbers change; every one of them is listed below.

## Numbers that changed

- Sampler gm noise was 3 dB low in analyze().  The gm stage injects one
  charge packet per reference cycle, which is a sampled sequence and
  carries the 2x alias factor into the one-sided PSD; it was modelled as
  a duty-cycled continuous current.  Effect: spll_100m_8g 201.1 ->
  207.6 fs, spll_frac_52m_6p253g 250.0 -> 258.0 fs, Wu'19 benchmark
  76.8 -> 80.9 fs, SSPLL family +0.2-0.3 fs (kT/C dominates there).
- Reference spur was 6 dB optimistic in all three analog architectures.
  Narrowband FM puts the sideband at beta/2 with beta = Kvco*V1/fref;
  the code carried an extra factor of 2 inside beta and halved again.
  README.md had the correct expression all along.  Every ref_spur
  reading is now 6 dB worse.
- DTC random jitter never reached the CPPLL or ADPLL budgets, though
  every fractional engine injects it each cycle.  Effect: fractional
  CPPLL +0.4 fs, Dartizio'23 benchmark 56.8 -> 58.9 fs, and in
  bang-bang ADPLL it now also moves the predicted loop bandwidth
  through the BBPD's sigma_t.
- Charge-pump flicker noise was in analyze() but never injected in the
  time domain, so the two domains disagreed by ~2 dB once the CP
  dominated.  Time-domain CP noise now carries the 1/f component.
- ILCM and MDLL reported different quantities under the same name:
  fine_oversample defaulted to 0 on one and 4 on the other, and only
  MDLL recomputed jitter from the oversampled phase.  Both now default
  to 4 and integrate the same thing; SimResult.notes says which.

## Things that used to be silently ignored

- ADPLL.simulate() advertised mod_freq, kdco_cal, tdc_cal,
  dtc_gain_init_error and dtc_gain_drift on one signature but handed
  each mode only its own subset.  A bang-bang two-point modulation run
  returned a normal-looking result with NO modulation in it.
  Unsupported combinations now raise.
- OscConfig's tuning knobs (nl1/nl2, v_min/v_max, band offset) reached
  only three of six engines; ADPLL and MDLL now evaluate the same
  freq_law, and ILCM — which has no tuning law at all, its FTL corrects
  frequency directly in Hz — rejects them with the reason.
- fll_stability() raised AttributeError on every architecture without
  an FLL; it now says the question does not apply.
- The selector treated a modulation requirement as advisory, so it
  could recommend an architecture whose engine cannot modulate.  Now a
  hard gate, with the fact derived from the engine rather than kept in
  three hand-maintained lists.
- ADPLL in TDC mode never tabulated a spur despite taking a fractional
  FCW natively; adpll_100m_10g has a real -72 dBc beat at 600 kHz.
- jitter_fs could report an unconverged calibration: bench_dartizio23
  reads 8.6 ps at the GUIs' default 150k cycles against a 78 fs
  headline.  SimResult.notes now warns, and both workbenches show it.
- ILCM/MDLL analyze() published -600 dBc when called without a
  frequency error — log10(1e-30) reading as "spurless by design".

## Packaging and hygiene

- The Streamlit GUI now lives in the package (pllsim.webgui) and ships
  in the wheel, with a `pllsim-web` console script.  It previously sat
  outside src/, so `pip install pllsim[gui]` did not include it and the
  documented launch command only worked from a source checkout.
- pllsim.__version__ was pinned at "0.1.0" for five releases; it now
  reads the installed distribution metadata.
- The Benchmarks GUI page imported from tests/, which is not shipped in
  the exe — that button raised ModuleNotFoundError in the packaged
  build.  It builds from the bench_* presets now.
- The Spurs page's worst-channel sweep ignored the preset the user
  selected and always swept the first one.
- Four hardcoded copies of "the fractional presets" all still named the
  same four after v0.5.3 added three more; derived from ALL_PRESETS now.
- CI gained ruff and coverage, and runs all 20 examples instead of 2.

204 tests, up from 180; the new tests/test_conventions.py isolates one
noise source or mechanism at a time, since the existing cross-domain
tests compare totals with 2.5-3 dB tolerances and cannot see a 3 dB
error in a single contributor.
