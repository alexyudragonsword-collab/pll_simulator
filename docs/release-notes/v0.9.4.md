pllsim v0.9.4 — every architecture anchored, the library from a shell, and the gates that read counts

Four merged changes above v0.9.3 (P1-B, P2, P3 and a hygiene pass of the
health-check plan) with no version between them; this release names them.
Two stock figures move, both because a missing noise term was added and
said so: `adpll_bb_100m_10g` reads 139 fs in the time domain (114 before,
no feedback-divider noise existed for the bang-bang ADPLL) and the
Dartizio'23 anchor reads 76 fs against the published 77 (was 77).  Nothing
else in the linear model or the time domain changed for an existing preset.

## An anchor for every architecture

The CPPLL, ILCM and MDLL had no literature benchmark.  Three `bench_*`
presets, ex14 parts 4–6, tests and the deck table close that:

| paper | arch | published | model |
|---|---|---|---|
| Da Dalt & Sandner, JSSC 2003, 311 MHz → 2.488 GHz (N=8) | CPPLL | L(1 MHz) −115 dBc/Hz; 860 fs, no band given | −115.1 dBc/Hz; 258/244 fs over 12 k–20 M — the 860 fs is quoted, not matched, because a −115 dBc/Hz 1/f² profile cannot integrate to it in any band a 2.5 GHz clock is measured over |
| Helal, Hsu, Johnson & Perrott, JSSC 2009 PILO, 50 MHz → 3.2 GHz (×64) | ILCM | 130 fs | 130 fs time domain (83 fs linear; the ILCM's time domain is the reference) |
| Elshazly, Inti, Young & Hanumolu, JSSC 2013 digital MDLL, 375 MHz → 1.5 GHz (×4) | MDLL | 400 fs | 415 fs time domain (541 linear) |

Every undisclosed circuit value is a labelled assumption, as before; the
integration bands of the three are assumptions too, stated in each
docstring, because the abstracts give none and the full texts were not
reachable from where this was written.

## The model says where it stops describing an oscillator

The three analog loops evaluate an unbounded control-voltage law unless
`OscConfig.v_min/v_max` are set, and every stock preset leaves it unbounded.
That stays — the presets sit 0.6–1.0 V from f0 and the GUIs' default
−100 MHz hop travels 1.67 V on a 60 MHz/V oscillator, so any physical range
would turn the hop page into a rail demonstration — but it is a stated
boundary now, `tuning-swing` in the registry: `analyze()` notes when fout
needs more than ±1.5 V of travel with no range set, or lies outside a set
range; `simulate()` reads the run's own control-voltage tail and names the
rail, or the voltage it parked at.  The sweep exercises it at N = 260 on
the stock CPPLL (2.08 dB, inside the 2.5 dB base).

The bang-bang ADPLL's feedback divider makes noise: `div_pn_dbchz/div_pn_fc`,
None means not modelled and `analyze()` says so, tdc mode refuses them.
MASH-2 for the sampling loops was measured on the modulators (2 UI of
residue against 1.0–1.6 UI of shipped DTC range) and deferred; the refusal
message used to claim 4–8 UI and now carries the measured numbers.

The "still settling" detector compares cycle-to-cycle phase increments
instead of the phase std of the record's halves: with 1/f wander in a long
record the old ratio read 0.7–1.95 across seeds on a converged loop; the
new one reads 1.00–1.02 converged and 2.2 on a real transient.

## The forms speak engineering notation, and an edit can be kept

Every form, `--set` and the sensitivity gate accept and show `19.2M`,
`680p`, `2ms`, `100k`; ratios between 1e-3 and 1e3 stay plain.  Parsing
scales the decimal string rather than the float, so a round trip is exact
to the ULP.

A config file (`pllsim-config/1`) is a preset name plus every form field as
a JSON number: bit-exact round trip over all 18 presets, an unknown preset
or field refused by name rather than dropped.  The web workbench downloads
and uploads it, the Qt one has Save/Load, the phone passes it through a
text box.

`pllsim` is the library from a shell: `presets`, `fields`, `analyze`,
`simulate` (with a CSV record), `sweep` (a refusal is a row), `corners`,
`export`, `config`; `--config FILE` and `--set` compose.

The phone gained the Fit page (11 of the desktop GUIs' 13) over pasted
(offset, dBc/Hz) text; MonteCarlo stays out until the one-shot bridge has
a progress channel, Export stays out for good.

## A testbench that had failed for several releases, and gates that read counts

The FLL RTL's `cycles` port was a fixed 8 bits.  For N = 256 (the
Markulić'16 anchor) that truncated N itself to zero and every window read
ferr = −16384; ex13's index carried `fll:FAIL` for that preset since the
FLL export landed and nothing read the column.  The widths follow N now, a
bit-true test runs N = 256 (4033 mismatches before the fix), and ex13 exits
non-zero on any FAIL.

CI runs the suite on Python 3.10 with numpy 1.24.4 / scipy 1.8.1 /
matplotlib 3.7.5 pinned — the interpreter and wheels the phone runs — and
a step refuses if a GUI extra moves a pin.  That leg's first run would have
gone green 97 tests short: streamlit and PySide6 were not installed, and a
module-level `importorskip` reports a whole file as one skipped item.
`PLLSIM_CI=1` now turns a missing optional dependency into a failure in
both test jobs.  The main job runs on four workers; every workflow has a
timeout and a concurrency group; the two Windows workflows are one
reusable build (proven from main: a 107 MB Qt exe in 3.5 minutes); the
APK inspection is a unit-tested script rather than two heredocs.

## Hygiene

One source for the per-architecture DTC target mapping (was five copies),
for the GMSK/EVM and gain-ramp page recipes (eight bare `+4000`s), and for
`frac_spur_offsets` (now in `core`).  `__all__` names `validation` and
`cli` and a test pins it.  mypy checks unannotated bodies (eleven real
errors surfaced and were fixed); ruff adds B/UP/SIM and covers `docs/`;
every `zip()` states its strictness.
